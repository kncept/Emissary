# Object storage (S3)

Emissary stores inbound mail in a single Amazon S3 bucket. The bucket is
used as the read side of mail when `STORAGE=s3` (see
[CONFIGURATION.md](CONFIGURATION.md)); outbound mail is sent separately
through the configured [sender](ARCHITECTURE.md#outbound-mail-flow).

## Bucket layout

The bucket uses a structured layout organized by user and mailbox (per JMAP):

| Location | Key | Contents |
| --- | --- | --- |
| `users/<user-id>/` | `user.json` | Plain JSON write-out of the user record (`EmissaryUser`) for the `s3` user manager. A mailbox directory without this object is not a user. |
| `users/<user-id>/<mailboxId>/` | `<received-timestamp>_<ses-message-id>.eml` | Raw RFC 5322 message for a specific user's mailbox. |

- **user-id**: The user's email address (e.g., `alice@example.com`)
- **mailboxId**: JMAP mailbox id (e.g., `inbox`, `drafts`, `sent`, `trash`, `archive`, `junk`)
- **received-timestamp**: ISO 8601 UTC timestamp when the message was received (e.g., `2026-11-17T10:30:45Z`)
- **ses-message-id**: The original SES message ID from the receipt rule

Example key: `users/alice@example.com/inbox/2026-11-17T10:30:45Z_01000192a3b4c5d6-12345678-9abc-def0-1234-56789abcdef0.eml`

The message ID used throughout the JMAP API is the full delivered object key
(path), including the received timestamp and `.eml` suffix. It encodes the
account, JMAP mailbox, received time and SES message ID. Staging objects at the
bucket root are the *input* to delivery and are not mailboxes; their bare SES
message ids are not user-visible email ids.

## Inbound flow

1. SES receives mail for the domain and evaluates the active receipt rule
   set (created by the `emissary-in-<domain>` CDK stack).
2. The receipt rule's S3 action writes the raw message to a **staging area** at the bucket root
   with the SES message id as the key (this is the initial delivery by SES).
3. A consumer process (Lambda or scheduled job) reads from the staging area, determines the recipient(s),
   and for each valid recipient:
   - Parses the message to extract the received timestamp (`Date` header or `Received` headers)
   - Copies the object to `users/<recipient-email>/inbox/<timestamp>_<ses-message-id>.eml`
   - Deletes the staging object
4. When a user lists or opens mail, the application paginates
   `ListObjectsV2` over the prefix for the JMAP `accountId` on the call:
   `users/<accountId>/<mailboxId>/`. An absent `inMailbox` filter lists
   every mailbox in that account. The `accountId` comes from the JWT
   `sub`, or from the caller-supplied target when a System Manager is
   masquerading. Only objects that look like delivered messages — a
   per-user mailbox subfolder and a `.eml` suffix — are considered mail;
   system records such as `user.json` and other non-message objects are
   skipped. Objects that cannot be parsed are logged and skipped.

Deleting a message removes its object from the user's mailbox prefix and discards the
associated read/flag metadata. Each user has their own copy in their mailbox,
so deletion only affects that user's view.

## Configuration

| Variable | Description |
| --- | --- |
| `STORAGE` | Set to `s3` to read mail from S3. Defaults to `memory`. |
| `S3_BUCKET` | Bucket holding inbound messages. Required when `STORAGE=s3`. |

The application uses the default AWS SDK credential/config chain for the
region and credentials. In a local run, `S3_BUCKET` must be set
explicitly when using `STORAGE=s3`; for a fully local, AWS-free run use
`STORAGE=memory` (see [CONFIGURATION.md](CONFIGURATION.md#local-runs-runsh-run)).

## Deployment

The inbound CDK stack (`emissary-in-<domain>`) provisions the bucket
(public access blocked, SSE-S3, SSL-only), the receipt rule and the MX
record that delivers domain mail to SES. The bucket name is published to
SSM at `/emissary/<domain>/bucketname` for the application stack. The
application Lambda is granted `s3:GetObject`, `s3:ListBucket` and
`s3:DeleteObject` on the bucket.

See [DEPLOYMENT.md](DEPLOYMENT.md) and
[ARCHITECTURE.md](ARCHITECTURE.md#inbound-mail-flow) for the full
deployment and runtime picture.
