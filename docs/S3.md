# Object storage (S3)

Emissary stores inbound mail in a single Amazon S3 bucket. The bucket is the read side of mail when `STORAGE=s3` (see [CONFIGURATION.md](CONFIGURATION.md)); outbound mail is sent separately through the configured [sender](../mailer/components/sender/sender.go). It also holds user records for the `s3` user manager and the staging area consumed by inbound delivery ([ARCHITECTURE.md](ARCHITECTURE.md#inbound-mail-flow)).

## Bucket layout

The bucket uses a structured layout organized by user and mailbox (per JMAP):

| Location | Key | Contents |
| --- | --- | --- |
| bucket root | `<ses-message-id>` | Raw message staged by SES; delivery input, not a mailbox. |
| `users/<user-id>/` | `user.json` | Plain JSON write-out of [`EmissaryUser`](../mailer/components/usermanager/usermanager.go) for the `s3` user manager. A mailbox directory without it is not a user. |
| `users/<user-id>/<mailboxId>/` | `<received-timestamp>_<message-id>.eml` | Raw RFC 5322 message for a specific user's mailbox. |
| `_processed/` | `<sha256(staging-key, recipient)>` | Empty idempotency marker written after a recipient is handled; cleared when staging is deleted. |

- **user-id**: the user's email address, e.g. `alice@example.com`.
- **mailboxId**: a JMAP mailbox such as `inbox`, `drafts`, `sent`, `trash`,
  `archive` or `junk`.
- **received-timestamp**: ISO 8601 basic UTC (`YYYYMMDDTHHMMSS`, e.g.
  `20240308T143000`), derived from the `Date` header with a current-time
  fallback.
- **message-id**: the storage-generated id for new deliveries; older
  SES-message-id keys remain valid.

Example key: `users/alice@example.com/inbox/20240308T143000_9f1c0a4b2d6e8f7091a3b5c7d9e0f246.eml`. The JMAP id is the stable filename token, so moving a message changes its physical key but not its id. Staging objects are not user-visible mail, and their bare SES ids are not email ids. Default role mailboxes are ensured for accounts, and custom top-level mailboxes can be created with `Mailbox/set`; see [DESIGN.md](DESIGN.md#core-concepts) and [API.md](API.md#jmap-mail-operations).

## Inbound flow

1. SES receives mail for the domain and evaluates the active receipt rule set
   created by the `emissary-in-<domain>` stack.
2. The rule's S3 action writes the raw message to a staging area at the bucket
   root, keyed by the SES message id.
3. A consumer process (the `s3-receiver` Lambda or a scheduled job) parses the
   staged object and collects SMTP envelope recipients from the topmost
   `Received` header's `for <address>` clauses; `To`, `Cc` and `Bcc` are never
   used for routing. See [ARCHITECTURE.md](ARCHITECTURE.md#inbound-mail-flow)
   for recipient rules.
4. For each recipient, the consumer calls `Storage.AddEmail` on the configured
   store with the original bytes. With `STORAGE=s3`,
   [`S3Storage.AddEmail`](../mailer/components/storage/s3.go) derives the
   timestamp from the `Date` header, generates the id, and writes
   `users/<recipient>/inbox/<timestamp>_<id>.eml` verbatim, preserving headers,
   MIME parts, encodings and attachments.
5. Metadata is created from the returned id with no keywords and a
   server-stamped `receivedAt`
   ([CONFIGURATION.md](CONFIGURATION.md#metadata-jmap-keywords-and-received-time)).
   A per-recipient marker under `_processed/` lets retries skip completed
   recipients; staging is deleted only after all recipients succeed.
6. Listing and reading resolve the JMAP `accountId` to the internal user id and
   paginate `users/<internal-user-id>/<mailboxId>/`. Non-`.eml` system objects
   and unparseable messages are skipped. Deleting a message removes its object
   and metadata; each recipient has their own copy.

See [SUPPORT.md](SUPPORT.md#bucket-root) for the staging tools and
[SUPPORT.md](SUPPORT.md#processing-a-staging-email) for manual processing.

## Configuration and deployment

| Variable | Description |
| --- | --- |
| `STORAGE` | `s3`, or inferred when AWS credentials plus `S3_BUCKET` are the sole configured storage backend. `memory` is an explicit opt-in. |
| `S3_BUCKET` | Bucket holding inbound messages; required for `STORAGE=s3`. |

The default AWS SDK credential/config chain supplies credentials and region.
For a fully local, AWS-free run use `STORAGE=filesystem ./run.sh run`
(persistent) or `STORAGE=memory ./run.sh run`; see
[CONFIGURATION.md](CONFIGURATION.md#aws-and-local-runs) and
[DEVELOPMENT.md](DEVELOPMENT.md#run-locally).

The inbound CDK stack provisions the bucket (public access blocked, SSE-S3,
SSL-only, objects removed on teardown), the SES receipt rule and the MX record
for the domain. The bucket name is published to SSM at
`/emissary/<domain>/bucketname` for the application stack, whose Lambda gets
bucket read/write/delete permissions; see
[DEPLOYMENT.md](DEPLOYMENT.md#emissary-in-domain--inbound-mail) and
[CONFIGURATION.md](CONFIGURATION.md#backend-selection-all-pluggable-components).
